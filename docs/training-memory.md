# 显存容量与随机窗口裁剪

混训入口在八卡时默认加载 [`sequence_capacity_8npu.json`](../wan_va/configs/sequence_capacity_8npu.json)。目标是保留长样本，通过随机连续机器人窗口限制显存。集群设置与启动命令见 [八卡训练说明](cluster-training.md)。

## 生效范围与规则

该配置标定于 8×64 GiB Ascend 910B3，FP32 初始化/BF16 计算、FP32 reduce、FSDP2 sublayer、完整激活检查点、4 个 MCP、每卡 batch 1、梯度累积 1。代码校验模型结构和主要训练设置；改变设备或并行策略后需要重新验证。

令 `R = 机器人视频 tokens + 动作 tokens`，`H = 完整人类视频 tokens`。容量配置记录以下实测通过点，并预留 5% 机器人 token 余量：

| 可覆盖的 H | 通过的 R | 留余量后的 R 预算 |
| ---: | ---: | ---: |
| 2,240 | 19,700 | 18,715 |
| 2,520 | 19,475 | 18,501 |
| 3,600 | 19,364 | 18,395 |
| 4,464 | 19,320 | 18,354 |
| 6,624 | 19,158 | 18,200 |

从能覆盖当前 H 的通过点中选择最大的 R，乘 0.95 向下取整，再除以每机器人帧的视频与动作 token 数，得到最大窗口帧数。H 超过已测范围时明确报错。5% token 余量不是精确的显存余量，也不保证任意数据或分配器状态下均不会 OOM。

裁剪在 CPU 上、传入设备之前执行。短样本保持原样；长样本每次从所有合法起点中均匀随机抽取，视频、动作及动作掩码同步裁剪。完整人类示范和文字不因窗口裁剪而截短；训练的条件 dropout 独立执行。起点随机不等于各帧被选概率相同，也不保证有限次训练覆盖完整轨迹。

这是预计算 latent 的切片，中间窗口不等同于从原始视频重新编码的独立片段。Wan VAE 的首帧和历史边界语义仍需单独验证；容量和吞吐测试不验证这一建模假设。

同样帧数因空间尺寸、相机数、动作步长或 H 不同，显存需求可相差很大。分桶成本使用实际裁剪后的 `2R+H`，保留原先抽到的样本多重集合，但重排会改变优化轨迹。

## 启动选项

| 环境变量 | 行为 |
| --- | --- |
| `SEQUENCE_CAPACITY_PROFILE=/path/to/profile.json` | 指定容量配置；八卡默认使用仓库配置 |
| `SEQUENCE_CAPACITY_PROFILE=off` | 关闭容量裁剪 |
| `MAX_TRAIN_FRAMES=64` | 可选额外机器人帧数上限，与容量上限取较小值 |
| `LENGTH_BUCKET_STEPS=10` | 混合来源默认分桶窗口；设 0 关闭，单来源默认关闭 |
| `FSDP_GRANULARITY=sublayer` | 默认粒度；改用 block 不符合这份容量标定 |
| `FSDP_ASYNC_UNSHARD=1` | 混训入口默认启用当前流上的 FSDP2 all-gather 分配；设 0 恢复原路径，不关闭反向预取 |
| `PYTORCH_NPU_ALLOC_CONF=expandable_segments:False` | 混训入口默认普通缓存分配器，显式设置优先；通用环境脚本的默认值未改变 |
| `TRAIN_DIAGNOSTICS=1` | 记录逐卡样本、形状、显存、分配重试及异常，增加同步与日志开销 |

其他卡数不自动加载八卡容量配置。直接调用 `wan_va.train` 时需显式传入 `--sequence-capacity-profile`。裁剪日志包含原始帧数、保留帧数、起止位置及 profile 名；`metrics.jsonl` 的 `rank0_window_crop` 仅代表 rank 0 当前微步。

## 内存优化与验证范围

当前保留稠密 mask 按行分块构建、同一步 MCP mask 复用、全屏蔽 padding 行语义修正、FSDP2 及激活检查点。最终 bool mask 仍为二维稠密矩阵，FSDP 也不分摊每卡的完整序列激活。

时间步嵌入改为每 latent 帧计算一次，AdaLN 保留帧级投影与 token 到帧的映射，逐组展开调制参数，避免长期保留逐 token 的六组投影及一次性生成对应的大 FP32 张量。帧级展开的梯度累加通过输出、梯度和激活检查点对照测试。

NPU 的 Q/K RMSNorm 使用融合实现，FP32/BF16 输出与输入、权重梯度通过设备对照测试。FSDP2 异步 unshard 调整 all-gather 暂存区的分配流及释放时机，降低长序列的分配等待；这是通信缓冲策略调整，计算精度、分片粒度和梯度归约语义不变。短序列可能因通信重叠方式改变而有小幅波动，应比较代表性混合子集的总体吞吐。

长序列未 OOM 时仍可能反复触发显存回收。旧扩展段配置下，实测停顿集中于张量分配及 FSDP all-gather 缓冲区申请，并传播为其他卡的通信等待。混训入口使用普通缓存分配器以减少此处开销；启动前若已设置该变量，入口不会覆盖。`TRAIN_DIAGNOSTICS=1` 的 `success` 事件包含 `allocator_retries` / `allocator_ooms`；应结合耗时和利用率判断，重试计数为零不代表所有分配都没有停顿。

2026-09-18，上述优化在八卡真实子集上完成两类验证：40 条容量案例覆盖 17 种空间/动作布局，每条完成两步（另有两步全局预热），峰值 allocated 45.50 GiB；24 条代表轨迹通过生产加权采样与分桶，完成 64 步稳定性测试，跨越两轮子集采样及周期性缓存清理，峰值 allocated 44.55 GiB。全部步骤 loss 有限，无记录 OOM 或优化器跳步，裁剪对齐检查通过。测试保留完整条件（dropout=0），正式训练使用 0.1/0.4。

与最初优化前对齐同样本、裁剪和分桶的 14 个稳态步骤，平均单步从 23.25 秒降至 11.74 秒（吞吐约 +98%），时间加权 AICore 利用率从 47.9% 升至 83.9%，峰值 allocated 从 56.48 GiB 降至 44.55 GiB；其中最长组从 112–116 秒降至约 38 秒。单独比较融合 RMSNorm 与异步 unshard 的增量，64 步中的 40 个对齐稳态步骤从平均 12.05 秒降至 11.15 秒，吞吐约 +8.1%。

每组重复三次，排除预热与首次形状切换，使用同步诊断计时和约两秒间隔的利用率采样。子集分布及这些计时不代表全量训练的精确吞吐；分配器仍有重试，驱动 HBM 占用也不等于 allocated。部分桶内仍有较大的卡间长度差异，短序列 rank 的低利用率可能来自等待长序列 rank，不能只凭 util 或重试计数判断瓶颈。

上述验证不覆盖全量数据、长期收敛、多机或八卡 checkpoint 保存。长序列即使能容纳，吞吐仍可能明显下降；容量上限不是吞吐最优上限。逐步日志与历史实验流水留在本机被 Git 忽略的输出目录，不作为集群启动依赖。
