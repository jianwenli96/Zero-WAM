# 显存容量与随机窗口裁剪

混训入口在八卡时默认加载 [`sequence_capacity_8npu.json`](../wan_va/configs/sequence_capacity_8npu.json)。目标是保留长样本，通过随机连续机器人窗口限制显存。集群设置与启动命令见 [八卡训练说明](cluster-training.md)。

## 生效范围与规则

该配置标定于 8×64 GiB Ascend 910B3，FP32 初始化/BF16 计算、FP32 reduce、FSDP2 sublayer、完整激活检查点、4 个 MCP、每卡 batch 1、梯度累积 1。代码校验模型结构和主要训练设置；改变设备或并行策略后需要重新验证。

令 `R = 机器人视频 tokens + 动作 tokens`，`H = 完整人类视频 tokens`。容量配置记录以下实测通过点，并预留 5% 机器人 token 余量：

| 可覆盖的 H | 通过的 R | 留余量后的 R 预算 |
| ---: | ---: | ---: |
| 2,240 | 19,700 | 18,715 |
| 2,520 | 19,475 | 18,501 |
| 3,600 | 19,364 | 18,395 |
| 4,464 | 19,320 | 18,354 |
| 6,624 | 19,158 | 18,200 |

从能覆盖当前 H 的通过点中选择最大的 R，乘 0.95 向下取整，再除以每机器人帧的视频与动作 token 数，得到最大窗口帧数。H 超过已测范围时明确报错。5% token 余量不是精确的显存余量，也不保证任意数据或分配器状态下均不会 OOM。

裁剪在 CPU 上、传入设备之前执行。短样本保持原样；长样本每次从所有合法起点中均匀随机抽取，视频、动作及动作掩码同步裁剪。完整人类示范和文字不因窗口裁剪而截短；训练的条件 dropout 独立执行。起点随机不等于各帧被选概率相同，也不保证有限次训练覆盖完整轨迹。

同样帧数因空间尺寸、相机数、动作步长或 H 不同，显存需求可相差很大。分桶成本使用实际裁剪后的 `2R+H`，保留原先抽到的样本多重集合，但重排会改变优化轨迹。

## 启动选项

| 环境变量 | 行为 |
| --- | --- |
| `SEQUENCE_CAPACITY_PROFILE=/path/to/profile.json` | 指定容量配置；八卡默认使用仓库配置 |
| `SEQUENCE_CAPACITY_PROFILE=off` | 关闭容量裁剪 |
| `MAX_TRAIN_FRAMES=64` | 可选额外机器人帧数上限，与容量上限取较小值 |
| `LENGTH_BUCKET_STEPS=10` | 混合来源默认分桶窗口；设 0 关闭，单来源默认关闭 |
| `FSDP_GRANULARITY=sublayer` | 默认粒度；改用 block 不符合这份容量标定 |
| `TRAIN_DIAGNOSTICS=1` | 记录逐卡样本、形状、显存及异常，增加同步与日志开销 |

其他卡数不自动加载八卡容量配置。直接调用 `wan_va.train` 时需显式传入 `--sequence-capacity-profile`。裁剪日志包含原始帧数、保留帧数、起止位置及 profile 名；`metrics.jsonl` 的 `rank0_window_crop` 仅代表 rank 0 当前微步。

## 内存优化与验证范围

当前保留稠密 mask 按行分块构建、同一步 MCP mask 复用、全屏蔽 padding 行语义修正、FSDP2 及激活检查点。最终 bool mask 仍为二维稠密矩阵，FSDP 也不分摊每卡的完整序列激活。

2026-09-18，接入裁剪后的八卡容量子集共计划 40 条：24 条各完成两步、8 条完成一步、8 条未测；已完成步骤无记录 OOM，峰值 allocated 56.76 GiB。另一次混合吞吐子集完成 24 步，无记录 OOM，峰值 allocated 56.48 GiB。两者均从真实轨迹加载，已完成 loss 有限且无优化器跳步，按用户要求提前停止；测试保留完整条件（dropout=0），正式训练使用 0.1/0.4。

上述验证不覆盖全量数据、长期收敛、多机或八卡 checkpoint 保存。长序列即使能容纳，吞吐仍可能明显下降；容量上限不是吞吐最优上限。逐步日志与历史实验流水留在本机被 Git 忽略的输出目录，不作为集群启动依赖。
