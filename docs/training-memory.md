# 训练显存、长序列裁剪与性能

本文合并 2026-09-17/18 的 7 卡验证、性能优化、8 卡容量排查和随机窗口说明。当前策略是**保留长样本，超预算时随机裁机器人窗口**。原始日志和逐样本结果保留在本机被 Git 忽略的 `outputs/`、`train_out/`；本页保留可随仓库查阅的结论。

## 当前训练行为

在 CPU 上、搬到 NPU 前，对机器人 latent、动作及动作掩码同步取连续窗口。短样本保持原样；每次采到长样本重新抽起点，末尾窗口也可被抽到。人类示范和文字条件始终完整保留，两侧视频没有逐帧对应关系。

[`train_humangen_wan_npu.sh`](../script/train_humangen_wan_npu.sh) 在分配 **8 卡** 时默认启用[容量配置](../wan_va/configs/sequence_capacity_8npu.json)。以下命令只展示配置：

```bash
ASCEND_RT_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 \
  bash script/train_humangen_wan_npu.sh --dry-run
```

分配到空闲设备后可改为 `--run`，并设置新的 `ZERO_WAM_SAVE_ROOT`。

| 设置 | 行为 |
| --- | --- |
| `SEQUENCE_CAPACITY_PROFILE=off` | 关闭按容量裁剪 |
| `SEQUENCE_CAPACITY_PROFILE=/path/to/profile.json` | 使用指定容量配置 |
| `MAX_TRAIN_FRAMES=64` | 额外固定上限，与容量上限取较小值 |
| `LENGTH_BUCKET_STEPS=10` | 混合数据默认按预计 token 数分桶；单来源默认关闭，设为 0 可显式关闭 |
| `INIT_WORKERS=1` / `LOAD_WORKERS=2` | 默认串行初始化任务，每个训练 rank 使用两个 CPU 加载 worker |
| `FSDP_GRANULARITY=sublayer` | 默认 FSDP2 粒度；`block` 仅作实验选项 |
| `TRAIN_DIAGNOSTICS=1` | 逐卡记录样本、形状、显存、同步耗时与异常 |

其他卡数不自动使用 8 卡配置，仍可手动限制 `MAX_TRAIN_FRAMES`。直接使用 `wan_va.train` 需显式传 `--sequence-capacity-profile wan_va/configs/sequence_capacity_8npu.json`。

裁剪日志记录 rank、原长、窗口起止和保留长度。`metrics.jsonl` 的 `rank0_window_crop` 仅是 rank 0 当前微步的记录，不是全局裁剪率。分桶成本使用裁剪后的形状；启用容量配置时，动作 token 数从实际动作步长计算。

## 容量规则及适用范围

测量条件：独占 8×Ascend 910B3（标称 64 GiB），优化后的 dev、FSDP2 sublayer、FP32 权重/BF16 计算与 FP32 归约、激活检查点、4 个 MCP、每卡 batch 1、梯度累积 1。代码校验卡数、精度、MCP 和主要模型结构；改变硬件等未检查条件时仍需重新标定。

令 `R = 机器人视频 tokens + 动作 tokens`，`H = 完整人类视频 tokens`。实测通过点组成以下边界：

| 可覆盖的 H | 通过的 R | 预留 5% 后的 R 预算 |
| ---: | ---: | ---: |
| 2,240 | 19,700 | 18,715 |
| 2,520 | 19,475 | 18,501 |
| 3,600 | 19,364 | 18,395 |
| 4,464 | 19,320 | 18,354 |
| 6,624 | 19,158 | 18,200 |

选择所有能覆盖当前 H 的通过点中最大的 R，乘 0.95 后向下取整，再除以每机器人帧的视频与动作 token 数，得到窗口上限。起点在所有合法位置均匀抽取，沿用各 rank 的 PyTorch 随机种子。人类条件超过已测范围时明确报错。

5% 是机器人 token 余量，不是精确的显存余量，也不保证任何分配器历史下都不 OOM。相同帧数因空间尺寸、相机数、动作步长和人类示范不同，显存需求可能相差很大。例如 14×54、动作 8 tokens/帧、人类 46 帧的 RoboCOIN 样本上限为 92；更宽的 12×66 样本可降至 88。RoboMind 单摄像头 175 帧样本仍可完整保留。

## 数据影响

统计针对本机 **37,387 个有效训练片段**，含 RoboTwin 43 个训练任务，并非各来源官方完整数据集。全量只扫描形状元数据；早期容量边界测量使用物化小子集，后续裁剪验收通过原生 loader 读取真实轨迹。

| 来源 | 片段数 | 原始机器人 latent 帧中位数 / 最大值 | 当前会裁窗口 |
| --- | ---: | ---: | ---: |
| AgiBot | 6,659 | 19 / 195 | 73 |
| InternData-A1 | 11,230 | 44 / 159 | 155 |
| OXE | 5,165 | 9 / 20 | 0 |
| RoboCOIN | 6,102 | 53 / 177 | 1,241 |
| RoboMind | 6,082 | 19 / 175 | 124 |
| RoboTwin | 2,149 | 11 / 52 | 0 |
| 合计 | **37,387** | — | **1,593（4.26%）** |

样本删除数为 **0**。每条各抽一次时，保留机器人 latent 帧数之和为原来的约 96.40%，未按混合采样权重加权。均匀抽窗口不保证每一帧有相同采样概率，也不保证有限次训练覆盖全轨迹。

此前若采用过滤，保守排除边界未知及推断超限样本共 1,402 条（3.75%）；再留 5% 机器人 token 余量为 1,593 条。现在这些样本改为裁剪保留。该比例来自实测与形状推断，不是逐条训练确认的 OOM 比例。

## 实测依据与边界

初轮测试抽取真实轨迹做前缀边界探测；后续批量测试使用自然完整序列、保留完整人类条件并强制 ICL 存在。批量计划 83 个代表案例，停止前有效轮次尝试 27 个，其中 **16 通过、5 OOM、6 被同轮异常中断**。另有 56 个尚未尝试，合计 62 个没有判定。004/005 轮发生外部占卡争用，结果已剔除，不能作为容量证据。

5 个有效 OOM 均来自 RoboCOIN：tableware 分类 H46/R94、重复摆水果 H46/R98、搅咖啡 H31/R99、舀咖啡豆 H46/R98 和 H31/R99（这里 H/R 为人类/机器人 latent 帧数）。代表边界：

| 输入条件 | 通过 | OOM |
| --- | --- | --- |
| RoboCOIN，机器人 12×66，动作 8 tokens/帧，人类 18×32、46 帧 | 机器人 93 帧 | 94 帧 |
| RoboCOIN，机器人 14×54，动作 8 tokens/帧，人类 46 帧 | 机器人 97 帧 | 部分样本 98 帧 |
| RoboMind 单摄像头 14×18，人类 46 帧 | 机器人 175 帧 | 未测得 |
| OXE / RoboTwin 的已测最长样本 | 机器人 20 / 52 帧 | 未测得 |

近边界成功样本的峰值 allocated 约 59 GiB。批量测试确实使用每 rank 2 个 CPU DataLoader worker，共 16 个；抽样主机 PSS 峰值约 21.9 GiB、共享内存约 0.64 GiB，但这只覆盖小子集，不能代表完整数据初始化的主机内存。

FSDP2 分摊模型状态，每卡仍处理完整序列激活。最初未优化的 7 卡版本在稠密注意力掩码整数临时矩阵处 OOM；优化后长序列仍可在 FFN/GELU 重计算反向或 MCP FP32 调制处 OOM。驱动占用、reserved 和 allocated 是不同指标。

历史 7 卡固定样本、完整人类 46 帧：机器人 80 帧通过、96 帧失败；人类截为 16 帧时 80 通过、88 失败。这些是优化前的不同实验档位，不能据此认为缩短人类示范降低了容量，也不能套用为当前 8 卡上限。

## 性能优化与验证

大注意力掩码按行分块构造，减少 Q×K 整数临时矩阵；同一步内四个 MCP 深度共用不可变掩码，下次 forward 重建。NPU 全屏蔽 padding 行显式清零，匹配参考输出与梯度。可选长度分桶在有限窗口内重排原先抽到的同一批样本，使各卡预计 token 数接近；它保留抽样多重集合，但会改变优化轨迹。

7 卡、机器人上限 64、完整人类示范、每卡 batch 1、分桶窗口 10 步的正式脚本验收：相同 210 次样本抽取，30 步全部完成。

| 指标 | 原实现 | 掩码优化＋分桶＋padding 修复 |
| --- | ---: | ---: |
| 第 2–30 步均时 | 33.22 s | 20.96 s |
| 30 步训练累计 | 1041.63 s | 673.82 s |
| 各卡 token 最大/最小比中位数 | 7.43 | 1.28 |
| 峰值 allocated | 50.24 GiB | 49.29 GiB |
| 前 / 后 10 步总 Loss 均值 | 4.3774 / 2.7633 | 4.2889 / 2.7566 |

均时降低 36.9%，不含模型/数据初始化、成本索引和保存；最终成本索引另耗时 80.53 秒。block 分片减少通信调用次数，但没有测得额外整网提速，默认仍为 sublayer。短程 Loss 下降不等于长程收敛。

历史性能验收有 CPU 102 项、NPU 8 项通过记录。新增容量裁剪相关主测试 37 项通过，后补 3 项启动脚本检查通过，模型 patch size 校验单独复测通过；另有 11 条真实样本 CPU 裁剪核验，确认模态对齐、完整条件保留和成本估算一致。随机容量裁剪接入后已进行下述八卡真实子集训练；容量边界本身仍来自此前实测加余量，尚未逐条验证全量数据。窗口可能只包含任务中间步骤，完整文字/人类示范仍描述原任务，其训练效果需后续评估。

## 2026-09-18：接入裁剪后的八卡验收

两次测试均使用 `3ad2b52` 的模型/训练实现、FP32 初始化、BF16/FSDP2 sublayer、四个 MCP、完整激活检查点、每卡 batch 1、累积 1、初始化 worker 1、加载 worker 2。为控制负载，子集测试关闭 human/text dropout、保留完整条件；正式训练入口仍为 0.1/0.4。仅改用子集数据入口及诊断包装，没有替换模型、损失或优化器。

| 测试 | 完成范围 | 已完成结果 |
| --- | --- | --- |
| 容量子集 | 计划 40 条，覆盖 17 种空间/动作步长组合；24 条各完成两步，8 条完成一步，8 条未测 | 无记录 OOM，loss 有限、无优化器跳步；峰值 allocated 56.76 GiB |
| 吞吐子集 | 六来源各选 4 个 token 成本分位，实际生产权重 sampler 抽样并以窗口 10 分桶；计划 32 步，完成 24 步 | 无记录 OOM，loss 有限、无优化器跳步；峰值 allocated 56.48 GiB |

容量子集包括历史 OOM 案例，两个 99 帧机器人样本裁到 93 帧后各连续两步通过。逐次检查确认视频/动作/mask 窗口同步且人类/文字条件完整保留。两次测试均在用户要求下提前停止，未完成案例不能标记为通过；吞吐测试第 25 步中断。上述八卡子集未运行 checkpoint 保存，不证明正式长训、全量数据或其他硬件均不会 OOM。

吞吐测试跳过两步预热和每组首次执行，得到 14 个重复步：短序列约 4.5–4.6 秒，中等约 8–12.4 秒，最长组（主干 2R+H 约 3.6–4.1 万）约 114.3 秒、AICore 利用率约 31%。最长组的两步占这 14 步总耗时约 70%；其前向约 24 秒、反向约 90 秒。反向时间包含重算和分布式等待，不能当作纯计算时间。

每步最慢 rank 的数据等待在重复步中平均约 5 ms；稳定阶段梯度裁剪与优化器合计约 0.22 秒。分桶对同一批 80 次抽样的成本均衡有效：每步最长/最短 token 比平均从 7.28 降至 1.30，抽样多重集合不变；这是 CPU 离线对照，不能据此声称实测提速倍数。

长序列 HBM 接近满载并反复回落、利用率波动，提示需要进一步检查内存管理、注意力、重算与通信。本轮未继续采集算子 profile，因此具体机制未确认。当前交接保留已验证实现，未恢复回退的 timestep embedding / scheduler 实验优化，未变更 FSDP 粒度或 checkpoint 策略。能容纳的窗口上限不等于吞吐最优上限。
